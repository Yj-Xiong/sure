# 阶段、执行约束与参考依据

Harness 将主客观联合分析拆成有顺序的阶段。下面的标准用于说明每一阶段的工作边界；它们不是把所有任务都宣称为某个标准的完整复现。

| 阶段 | 执行内容 | 必要检查 | 参考依据 | 适用边界 |
| --- | --- | --- | --- | --- |
| `resolve_task` | 确定评分维度、样本、候选、量表、参考角色和任务版本 | ID 白名单、候选角色、量表和值域齐全 | ITU-R BS.1284-2；P.808 | 用于组织听评任务和评分对象，不把任务自动宣称为完整 MUSHRA 或 P.808 复现 |
| `resolve_metrics` | 确定待分析的客观指标类型、方向、配对方式和模型条件分析范围 | 指标不重复；intrusive / non-intrusive、higher/lower better、paired/none 明确；排除 `hidden_reference` 和 `unprocessed` | ITU-R BS.1284-2；P.808 | 标准帮助定义评价对象和比较方式；具体指标清单由任务配置决定 |
| `validate_audio` | 固定音频版本并检查音频条件 | 可解码、采样率、声道、时长、文件哈希、响度和 True Peak | ITU-R BS.1770 | 只约束响度测量和节目音频条件，不替代任务自己的音频版本管理 |
| `run_objective` | 按指标计划计算逐条件客观分 | 同一任务、样本、候选、音频哈希和 engine route 配对；方向统一 | ITU-T P.1401；NIST 统计手册；指标自身的官方定义 | P.1401 和 NIST 用于结果组织与统计描述；具体指标输入要求由对应实现和锁定 engine 决定 |
| `ingest_subjective` | 保存原始听评并形成最新有效记录 | 原始提交不可覆盖；task/sample/candidate/scale/时间戳有效；重复键按最新有效记录覆盖 | ITU-T P.1401 | 约束数据记录和可追溯性，不规定本 Harness 的具体网页实现 |
| `aggregate_subjective` | 按样本 × 模型条件汇总 MOS、标准差和 CI95 | 完整候选组、有效人数、`n < 2` 的 CI95 不估计，不补分 | ITU-T P.1401；NIST 统计手册 | MOS 和区间是报告层；具体听评人数由任务设计决定 |
| `joint_analysis` | 在模型条件点上计算主观 MOS 与客观指标的 Pearson / Spearman | 只纳入模型候选；reference 和 unprocessed 不进入相关性；指标方向统一；共同条件点可追溯 | ITU-T P.1401；NIST Statistical Handbook | Pearson/Spearman 是描述性统计；共享样本和听评者时不把条件点当作完全独立样本给常规 p 值 |
| `screening` | 对主观评分做版本化敏感性分析 | 不看客观分、残差或相关系数；不整位删除听评者；保留 before/after | ETSI TS 103 281 V1.3.1 | 展示带和误差组织用于结果稳定性检查；具体评分标记规则必须单独版本化 |
| `render_report` | 输出排序、统计表、来源和失败诊断 | 产物存在、哈希一致、运行上下文和标准映射齐全 | ETSI TS 103 281 V1.3.1；ITU-T P.1401 | ETSI 的误差带和映射图示只借鉴组织方式，不把其具体 ±0.5 MOS 阈值移植到 0–100 量表 |

## 统一原则

1. 先确定指标计划，再开始客观计算。
2. 先固定音频和来源，再接收或汇总评分。
3. 所有阶段的输入、输出、版本和哈希写入运行上下文。
4. 标准没有规定的数值阈值必须写成 Harness 自己的版本化规则，不能冒充标准原文。
5. 失败时停止当前阶段并留下修复信息，不用旧产物、空表或未经声明的替代路径继续运行。
